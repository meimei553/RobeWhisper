RobeWhisper · 阶段 7 可行性与小步骤（先方案，后逐个击破）
========================================

前置核验（本回合已跑）：PHASE6_ACCEPTANCE_PASS / SITE 可访问 / 契约主字段未改

一、阶段目标
--------------------------------
把已跑通的阶段 0–6 收成「零基础可启动、可演示、可交付」产品面：
说明清楚、网站好懂、数据好找、真机有清单、回归有一页纸。
不新增仿真内核、不自训大模型、不推翻 TaskSpec。

二、可行性
--------------------------------
| 项 | 评级 | 说明 |
|---|---|---|
| 启动/依赖说明 | 高 | 已有 requirements、streamlit 入口、.env.example |
| 网站引导可读性 | 高 | frontend/app.py 已有聊天/摘要/配置区，只需打磨 |
| 实验/经验浏览 | 高 | experiment_store / experience_store 已落盘 |
| 真机联调清单 | 高 | HttpRobot/RosRobot + ROS接入说明 已有骨架 |
| 演示+回归一页纸 | 高 | 烟雾脚本齐全，整理命令即可 |

自主定案：
- 优先「文档 + 轻量脚本 + 网站文案」，少改核心业务
- 任何网站改动不得默认强制 USE_REAL_SIM_REAL / USE_REAL_ROBOT
- 全程友好失败文案；不改 TaskSpec / 三基类主契约
- 成熟工具优先：Streamlit、现有 JSON/CSV 导出，不自造新框架

三、不超过 5 个小步骤（先不写业务代码）
--------------------------------
步骤1：启动与依赖说明（零基础）
  - 根目录 README（或 使用说明.txt）：安装 Python 依赖、复制 .env、启动网站
  - 可选：Windows 一键启动 .bat（streamlit run frontend/app.py）
  - 验证：按说明可在新开终端启动；无密钥也能 mock 跑通

步骤2：网站引导与结果可读性
  - 首页阶段说明对齐「0–6 已具备能力」；关键开关旁短提示
  - 成功/失败回复更易读（少堆字段名，保留必要摘要）
  - 验证：未改 Pipeline 契约；默认 RSR/真机仍为关

步骤3：实验/经验浏览增强
  - 网站侧：最近实验/经验展示更清晰（时间、action、是否成功、RSR 有无）
  - 必要时整理 summary 可读字段；不改存储主路径
  - 验证：旧 experiments/ experience/ 仍可读；烟雾不回归失败

步骤4：真机联调检查清单
  - 在 plugins/robot 或 core 落「真机联调检查清单.txt」
  - 覆盖：USE_REAL_ROBOT、HTTP endpoint、ROS_DOMAIN_ID、无 rclpy 降级
  - 验证：仅文档/清单；不改 TaskSpec；缺配置仍回退 mock

步骤5：总演示剧本 + 回归一页纸 + 阶段7验收
  - 演示剧本（自然语言几句 + 勾选建议）
  - 回归命令一页纸（smoke_phase0…6 / smoke_phase6_step*）
  - 写阶段7验收.txt；全量回归；划清「二期/后续」边界（如 VLM）

四、步骤顺序
--------------------------------
1 启动说明 → 2 网站可读性 → 3 实验经验浏览 → 4 真机清单 → 5 演示+总验

五、本阶段故意不做
--------------------------------
- 重写 MuJoCo 引擎 / 自研物理
- 自训或微调大模型权重
- 推翻 TaskSpec / BaseEngine·BaseLLM·BaseRobot
- 默认强制开启真机或 RSR
- 视觉 VLM、完整产品级账号体系（二期）
