RobeWhisper · 总规划（微调版 · 1–10 成熟产品收口）
========================================
日期：2026-09-12
原则：机械臂主线；不自训大模型；不自研引擎；1–10 先闭环成可交付产品，11–15 后置。

【本次微调】
- 明确：第 1–10 期 =「完整、较成熟的产品面」（可答辩、可演示、可对外讲清边界）
- 第 11–15 期 = 后续增强（真机实验、真 RSR、接触抓取、多步、加分预留）
- 在进入 9、10 的同时，对 1–8 做「打磨包」（不改契约主字段、不推翻架构）
- **硬约束：做 9–10 时不得堵死 11–15**（不改主契约、不拆真机送单、不写死无物体/伪对照为唯一终局）

六、可行性评估
--------------------------------

| 块 | 可行性 | 说明 |
|---|---|---|
| 1–8 保持 + 轻打磨 | 高 | 已落地；打磨多为文案/小字段，风险低 |
| 第 9 期安全闸 | 高 | 引擎/Pipeline 侧加校验即可；不改 TaskSpec 主字段 |
| 第 10 期版本与标签 | 高 | 实验/经验 JSON 增字段；注意旧数据兼容（缺省值） |
| 1–10 作为「成熟产品」对外 | 高 | 故事完整；短板应用边界说清即可 |
| 把 11–12 硬塞进赛前/当前收口 | 中低 | 强依赖实验室与真机数据，易拖垮节奏 |
| 把 13 并进 1–10 | 中 | 接触场景改动面大；你已定物理后置，保持后置更稳 |
| 1–10 达到工业抓取成品 | 低 | 不做承诺；成熟=试机平台成熟，非产线臂成熟 |

总体结论：
**「先做完 9、10，并打磨 1–8，使 1–10 成为完整较成熟产品」——可行且推荐。**
风险主要在：安全闸阈值选太紧导致演示全失败；经验标签迁移弄坏旧键——用「只增字段 + 默认兼容」可化解。
