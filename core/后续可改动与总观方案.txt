RobeWhisper · 后续可改动清单与总观方案（先不动手）
========================================
日期：2026-09-14
前提：第 1–14 期已收口。本文只列可行性与推荐顺序，不改产品代码。
产品定位不变：机械臂自然语言试机平台；不上岗；仿真≠现实。


一、总观（先看这个再看条目）
--------------------------------
产品已经能讲完一条故事：
人话 → 任务单 → 仿真试机 → 记录/经验 → 安全闸 → 真机口（默认关）
→ 虚实对照（伪/真）→ 接触代理 → 多步编排。

再往下改，只有三类事情「总观上值得」：

甲、把试机故事补圆（软件能做、答辩能讲清边界）
乙、第15期加分（让别人点开、让说法更自然、让臂更好看）
丙、实验室才做得动的（视觉、力、真标定）——本期清单里标「不做」

原则：
- 先甲后乙。公网网址补不了「指令没落到场景」。
- 一次只开一条线，仍≤5 步、一步一验。
- 凡是要假装「看见/抓住/已标定」的，一律不进必做。


二、有可行性、值得考虑的改动（编程工具可推进）
--------------------------------

【甲类 · 试机主线补强】

A1 场景位姿示意（软件接地）——可行性：高；总观：高；合理性：高
    接触场景里按方块 xpos 让末端朝它伸，而不是写死关节角。
    无物体模型禁止编造坐标。文案：非相机、非抓住。
    详案已有：core/阶段_场景位姿示意_正式流程.txt

A2 接触指标写清楚一点——可行性：高；总观：中高；合理性：高
    第13期已有 grasp_proxy。可补：距离数值进诊断、阈值书面化、
    「够不着 vs 碰到 vs 场景没开」三种人话更稳。
    不升级成夹稳/力控。可并进 A1 步骤3，不必单独成期。

A3 多步失败即停的人话加固——可行性：高；总观：中；合理性：高
    第14期已逐步执行、失败标第几步。可补：诊断固定句式、样例「第二步故意失败」。
    条件分支（若碰到再放下）可行性中、合理性中偏低（易做成假智能），暂缓。

A4 平面臂简易几何（二连杆朝 xy）——可行性：高；总观：中；合理性：高
    是 A1 的实现手段，不是独立产品功能。不要单独立项叫「上 IK」。

A5 假接收端联调剧本一页纸——可行性：高；总观：中；合理性：高
    第12期已有 --with-trajectory。可补：从开假端到网站看到「真轨迹」的零基础步骤。
    偏文档，可放进第15期或 A1 总验时顺手，不单独开期。

A6 实验旁路统一「本次用了哪些代理」——可行性：高；总观：中；合理性：高
    一张表写清：grasp_proxy / pose_source / RSR 对照来源 / 是否多步。
    便于答辩。可挂在 A1 步骤3。


【乙类 · 第15期规划内（加分，不解决虚实鸿沟）】

B1 可视化预留（截图/简易 2D 杆图/现成 viewer，不是自研 3D 引擎）
    可行性：中高；总观：中（好看、好演示）；合理性：中高（用现成，不自研）
    总规划原词：3D 主视口预留。合理切法：引擎截图或超简 2D，禁止新开图形引擎项目。

B2 本机以外的可打开地址（Streamlit Cloud / Docker）
    可行性：中（依赖账号与 MuJoCo 云端环境）；总观：中（给别人看）；合理性：中
    密钥用 Secrets；演示默认仍可 mock。

B3 充值激活 Kimi/Moonshot，LLM_BACKEND=api
    可行性：中（额度/网络）；总观：中（说法更自由）；合理性：中
    失败必须回退 mock。不要让主演示绑死额度。

B4 启动/部署说明打磨（packages.txt、一键、失败人话）
    可行性：高；总观：中；合理性：高
    随 B2 做，不单独成期。


【丙类 · 看起来像功能、但合理性差或可行性低 —— 明确不做或后置很后】

C1 真视觉找物 / 颜色识别闭环 —— 可行性中低（数据与标定）；合理性：现阶低（易假）
C2 力控夹爪、抓稳判定 —— 可行性低（无硬件）；合理性：现阶低
C3 把 RSR 做成系统辨识/参数收敛论文级 —— 可行性中低；合理性：超出试机定位
C4 多用户云账号、工业安全 ISO —— 不做
C5 机械狗、完整力矩优化、自研引擎 —— 与总规划冲突，不做
C6 条件规划大模型自动拆工艺 —— 易吹过头，暂不做


三、按「总观性 × 合理性」排序后的推荐顺序
--------------------------------
第 1 波（建议下一期，先做完再谈 15）
    A1 场景位姿示意
    顺带：A2 接触人话、A4 几何示意、A6 旁路摘要（都塞进 A1 的 5 步里，不另开期）

第 2 波（总规划第 15 期）
    B1 可视化预留（克制） → B3 API 激活（有额度再开） → B2 公网部署
    文档：A5 假端剧本、B4 启动说明
    理由：先有「朝物体示意」再给外人看；先 API 回退策略再上云，避免云端挂在欠费上。

第 3 波（有实验室再说）
    真机一条重复轨迹 + 可选相机位姿输入（仍可先手填坐标，不自称视觉）
    C1/C2 仍默认不做，除非硬件和老师到位。


四、第 1 波正式方案（仍≤5 步，先不动手）
--------------------------------
目标：接触场景下 grab/place 朝仿真物体位置示意；默认臂不假接地。

步骤1 契约：pose_source / object_xpos 等旁路；无场景禁止假坐标
步骤2 引擎：有物体则按 xy 示意；Mock 可注入；失败回退旧示意但标明
步骤3 诊断落盘：人话「朝仿真方块，不是相机」；可带距离/接触一行（A2）
步骤4 网站：接触试机说明补边界；剧本一小段
步骤5 总验：回归 13/14；未开真发；未做第15期

详案：core/阶段_场景位姿示意_正式流程.txt
验收口径：有场景能看出「在朝方块去」；无场景与现在一样；文案无「看见/抓住」。


五、第 2 波（第15期）骨架（先记着，未开工）
--------------------------------
步骤建议（将来再拆正式流程）：
1. 可视化预留契约（截图或 2D，不自研引擎）
2. API 激活检查清单 + 失败回退 mock（有额度才改 backend）
3. 云端/Docker 按已有方案 D，Secrets 注密钥
4. 假端真轨迹 + 启动说明补一页
5. 总验：本机 1–14 不回退；云端挂了本机仍能演示

故意仍不做：C 类全部。
