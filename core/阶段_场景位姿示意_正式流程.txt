RobeWhisper · 正式方案 · 场景位姿示意（软件接地）
========================================
日期：2026-09-14
前置：第 1–14 期已收口。第 15 期（3D/部署/Kimi）不动。
本回合：只出方案 + 可行性，不改网站代码。
触发动手：你说「开始步骤1」后再逐步击破。
定位：1–14 之后、第15期之前的**软件补强**（不新开工业抓取线）。


一、本期一句话目标
--------------------------------
让「抓红色杯子/方块」在**接触试机场景**里，从「关节固定示意」，
升级为「朝场景里已知物体位置伸过去」——软件接地，不是视觉找物。

含义对齐：
- ✅ 教学级：物体位姿来自仿真模型（MJCF/运行时 xpos），末端朝该点示意；诊断写清来源
- ❌ 不是：相机识别、视觉伺服、IK 求解器论文、工业到达精度、抓住=成功


二、为什么做这个（相对博导指出的缺口）
--------------------------------
当下核心诉求的第一缺口是：指令要落到场景，而不是 target 只当标签。
编程工具在无实验室时，能做的最小对齐就是：**仿真里物体坐标已知 → 动作朝它去**。

不选「公网部署」：部署不缩小虚实鸿沟。
不选「再加强 RSR 假端」：第12期已能验收真优先。
接触代理第13期已有：本期只把「朝谁伸」接上，接触仍用 grasp_proxy，不升级成夹稳。


三、你的产品能获得什么
--------------------------------
| 维度 | 现在（1–14） | 本期之后 |
|---|---|---|
| grab 在默认臂 | 固定关节示意 | 不变（无物体，禁止编造坐标） |
| grab 在接触场景 | 大致朝方块的固定角 | 按物体当前/初始位置生成示意目标 |
| 诊断 | 接触代理 + 多步 | 多一行：朝场景物体示意（非相机） |
| 答辩 | 标签试机 | 能说明「标签 vs 场景坐标」的差别 |

现实用处：试机前暴露「指令物体名对了，但臂根本没朝物体去」。


四、现状盘点
--------------------------------
已有：
- 接触场景 `object_block` + 末端 `ee`；grasp_proxy 旁路
- grab 在 Mujoco 里仍是接近写死的关节角（约 0.8/-0.6）
- TaskSpec.target 仍是 red_cup 一类标签
- 默认模型无物体

缺口：
A. 引擎不读物体 xpos 来定目标
B. 无场景时若乱填坐标会假接地
C. 网站没把「朝方块示意」讲成人话


五、硬约束（不堵死 15、不毁 1–14）
--------------------------------
[ ] 不改 TaskSpec / SimResult / ApiResult **主字段名**（位姿只进 params 或 metrics）
[ ] 不拆 execute_task；真发默认关
[ ] 默认仍 builtin_arm2；无物体 → 无场景坐标，不报假成功
[ ] 不做视觉、力控夹爪、完整逆解库、公网部署、3D 主视口（第15期）
[ ] 文案禁止：看见杯子、已经抓住、标定完成


六、自主定案（档 A / 档 B）
--------------------------------
档 A（本期必做 · 高可行）：
1. 旁路约定（只增）：
   - `metrics.object_xpos`（有场景才有）
   - `metrics.ee_goal_xy` 或等价：本步示意要去的平面目标
   - `metrics.pose_source` ∈ {scene_model, none}
2. 接触场景 + grab/place：用物体 xy（平面臂）生成关节示意目标
   - 二自由度臂：可用几何近似（两连杆长度已知）或「朝向物体的有界角度」
   - 失败可回退旧固定示意，但必须标明 pose_source=none 或 uncertain
3. 无接触场景：pose_source=none；行为与第13/14期一致
4. 诊断一行人话：「朝仿真里的方块位置示意，不是相机看到的红色杯子」
5. 样例：沿用「切换接触场景并抓一次」；必要时加一句说明，不必新大按钮

档 B（不做）：
- RGB/深度相机、YOLO、视觉伺服
- 完整数值 IK / 奇异点处理
- 力控、夹爪开合与抓稳
- 真机用外部测量位姿闭环


七、可行性
--------------------------------
| 项 | 评级 | 理由 |
|---|---|---|
| 读 MuJoCo 物体 xpos | 高 | 第13期已有类似读取 |
| 平面臂朝 xy 示意 | 高 | 二连杆几何足够教学 |
| 无场景不假接地 | 高 | 与 grasp_proxy=no_scene 同一模式 |
| 到达误差工业级 | 低 | 明确不做 |
| 与视觉对齐 | 低 | 无相机 |

结论：**按档 A 做，可行，建议做。**
风险：用户以为已经「看到杯子」——用 pose_source + 硬文案化解。


八、不超过 5 步
--------------------------------
步骤1：位姿旁路契约
  - 字段名、pose_source 枚举、无场景禁止填假坐标
  - 验证：旧单步/多步 TaskSpec 不变坏；无场景 metrics 不含伪造 xpos

步骤2：引擎按场景物体生成 grab/place 示意
  - Mujoco：接触场景读 object_block，写关节目标或 ctrl
  - Mock：可注入 mock_object_xpos，保证无 MuJoCo 也能测
  - 验证：有场景时 pose_source=scene_model；无场景 none

步骤3：Pipeline / 诊断 / 落盘
  - 成功回复与诊断增加「场景位姿示意」一行
  - 实验旁路可记 pose_source（脱敏）
  - 验证：默认臂人话为「当前无试机物体，只是关节示意」

步骤4：网站说明与样例对齐
  - 能力区/接触试机说明补一句接地边界
  - 演示剧本补一小段
  - 验证：零基础能看懂「不是相机」

步骤5：总验 + 回归 + 勘误
  - 复跑 phase14 / phase13 / feature_visible 关键
  - 书面：未开真发；未做第15期；未宣称视觉/抓住
