一、本期一句话目标
--------------------------------
让自然语言从「一句一个动作」，升级为可演示的**多步试机编排**，并**适度扩充动作表**，
使人话能表达「先…再…」这类连续试机，而不是只会单次 grab/place/home。

「多步 / 扩动作」在这里的含义（务必对齐）：
- ✅ 教学/试机级：一句里可含 2～N 个有序子动作；动作白名单可读、可扩几个常用动作
- ❌ 不是：自主任务规划大模型、复杂装配工艺、工业路径优化、视觉找物后多步


二、你的产品能获得什么（相对第13期）
--------------------------------
| 维度 | 现在（1–13） | 第14期之后 |
|---|---|---|
| 自然语言 | 基本映射为单个 action | 可映射为有序 steps[] |
| 动作表 | grab / place / move / home | 白名单文档化 + 少量扩展动作 |
| 执行 | Pipeline 一次 run_task | 可按序执行多段，汇总轨迹/诊断 |
| 答辩故事 | 能试机、能接触代理 | 还能演示「先回零再抓」等连续指令 |

注意：params 里已有的 `"steps": 3` 是**单次动作内部仿真细分步数**，
与本期 TaskSpec 级 **steps[] 多任务编排** 不是一回事；实现时命名/文案必须分开，避免混用。


三、现状盘点（推导依据）

C. Pipeline / 真机 / 经验复用默认按「单 TaskSpec」假设，多步需兼容旧数据

五、自主定案（范围怎么切才可行）
--------------------------------
采用 **「有序子任务列表 + 小步扩表」**，分两档：

档 A（本期必做 · 高可行）：
1. **动作表书面化**：正式清单（中文名 / action 英文键 / 是否需 target / 备注）
2. **扩 1～2 个易实现动作**（建议优先）：
   - `wait`：短暂停顿（试机节拍，实现简单）
   - 或 `wave` / `open_pose` 类「姿态示意」（仅关节示意，不宣称夹爪真实开合）
   （最终键名在步骤1契约里钉死；宁少勿滥）
3. **TaskSpec 可选 `steps`**：
   - 元素形如 `{action, target, params?}`
   - 有 steps 时：按序执行；顶层 action 可作为摘要或首步冗余（契约里写清）
   - 无 steps：行为与第13期完全一致
4. **解析**：mock 关键词识别「先…再… / 然后」；Prompt 允许输出 steps
5. **Pipeline**：循环 run_task 或引擎提供 run_sequence；超时/安全闸逐步生效；实验可记 step 摘要
6. **网站**：样例句 + 诊断显示「第 i/n 步」；能力说明一句话

档 B（本期不做）：
- 并行 steps、条件分支（如果抓到再放下）
- 自动拆解任意长自然语言成工艺图
- 真机上强制多步事务回滚
- 可视化甘特图 / 3D 逐步动画主视口


六、自行评估可行性
--------------------------------
| 项 | 评级 | 理由 |
|---|---|---|
| 契约增加可选 steps[] | **高** | 只增字段；旧 JSON 缺省兼容 |
| mock「先A再B」解析 | **高** | 规则可测 |
| Pipeline 顺序执行 | **高** | 循环现有 run_task 即可 |
| 扩 1～2 个示意动作 | **高** | 关节目标即可，不碰夹爪 SDK |
| 经验复用多步键 | **中** | 需约定按整段 steps 哈希或退回逐步；可简化为「多步暂不复用经验」 |
| 真机一次 POST 多步 | **中** | 可仍逐步 execute_task；或一次发带 steps 的单；步骤里写清默认逐步 |
| 任意长句完美规划 | **低** | 明确不做 |

总体结论：
- **第14期按档 A 做：可行，建议做。**
- 风险：与 params.steps（仿真细分）撞名 → 用文案+字段路径区分（编排用 TaskSpec.steps）。
- 风险：超时文案「减少 steps」歧义 → 步骤3/4 改成人话「减少子动作数量或缩短单步」。


七、不超过 5 个小步骤
--------------------------------
步骤1：动作表 + 多步契约
  - 写下动作白名单（旧4个 + 本期新增）
  - TaskSpec 可选 steps[] 的形状、空/缺省语义、与单 action 关系
  - 验证：旧单步 from_dict/to_dict 不变坏；schemas 单测/烟雾

步骤2：解析（mock + Prompt）支持多步与新动作
  - 「先回零再抓红色杯子」→ steps 含 home + grab
  - 非法动作拒识；过长 steps 可截断或拒绝（订上限，如 ≤5）
  - 验证：单测可复现；旧单句仍出单 action

步骤3：Pipeline / 引擎顺序执行 + 安全/超时
  - 按 steps 逐段执行；任一步失败则停并人话说明第几步
  - 汇总 trajectory / message；实验旁路可记 step_count
  - 真机：默认逐步送单或整单带 steps（选更简单者，步骤内钉死）
  - 验证：2 步成功；第 2 步故意失败可定位

步骤4：网站样例、诊断、能力说明
  - 聊天样例按钮；诊断显示多步进度
  - 演示剧本补一小节；区分「仿真细分步」与「多步编排」
  - 验证：零基础能点样例走通；旧演示不破

步骤5：总验 + 回归 + 勘误
  - smoke_phase14；复跑 phase13 / feature_visible / phase9 关键
  - 书面：未默认开真发；未做第15期部署；未堵死 3D/Kimi
  - 总规划勾第14完成态
