## 二、我对你需求的理解（浓缩）

你要的不是“会聊天的网页”，而是：

> **带物理底座的机器人自然语言编程平台**：人说话 → AI 解析成机器意图 → 在带真实参数的虚拟机器人上试跑出数据 →（可选）同一套意图发给真机 → 真机反馈再改仿真参数。

工作流应固定为一条链，避免模块互相打架：

```
自然语言 / 参数面板
        ↓
LLM 意图解析（System Prompt → JSON / 动作序列）
        ↓
统一任务协议 TaskSpec（全系统唯一“货币”）
        ↓
仿真引擎执行（物理参数已内置/已导入）
        ↓
实验数据 + 经验库
        ↓
[/execute_task] → ROS/真机（后期）
        ↓
真机轨迹回流 → 校准物理参数 → 写回仿真
```

**关键设计原则：**  
全系统只认一种中间物——`TaskSpec`（结构化任务描述）。前端、LLM、仿真、真机、回流，都只围绕它读写。这样模块拆开做，最后也不会“两种代码互相不兼容”。

## 三、最终方案（成熟产品向 · 地基分层）

### 总原则（每一步都要遵守）

1. **先契约，后实现**：阶段 0 定死接口与数据格式，后面只填实现。  
2. **一期只做“可演示闭环”**：①+② 完整；③ 只预留接口 + 假执行器。

4. **训练 = 经验库，不是训大模型**：成功轨迹入库、失败标记原因、相似指令优先复用。  
5. **前端永不抛栈**：后端失败 → “思考遇到阻碍，请稍后再试”。  
6. **做完一步：自测清单 + git commit + 再问下一步**（你说的“自行勘误”写进流程）。

### 阶段 2 · 模型导入 + 物理参数面板（2–3 天）

**做什么**  
- 导入：优先 **URDF**（形状尺寸 + 关节限位）  
- 参数面板：质量、摩擦、关节限位、阻尼等（勾选/填写）

**为何有理**

**勘误标准**  
换一个模型不崩；改摩擦后接触/滑动行为有可观察差异。

**本阶段禁止**  
自然语言主流程、真机、视觉。

**还可能出现，但概率已经小很多。**

### 原因
Streamlit 改代码后常做「热重载」，有时只更新一部分模块，就会出现「页面在 import 新函数，内存里还是旧模块」→ `ImportError`。

### 我们已经做的防护
表格函数已挪到独立的 `core/browse_tables.py`，网站从这里导入，不再依赖 `experience_store` 半旧缓存，这类问题会少很多。

### 若以后又报类似错
按顺序做即可：

1. **彻底重启网站**（最有效）  
   - 关掉正在跑的 Streamlit（黑窗口或占用 8501 的进程）  
   - 再让我帮你打开，或双击 `一键启动网站.bat`  
   - 浏览器 **Ctrl+F5** 强制刷新  

2. **清 Python 缓存**（仍不行时）  
   在项目根目录删掉各处的 `__pycache__` 文件夹，再重启网站。

3. **别只靠浏览器刷新**  
   热重载不可靠时，必须重启 Streamlit 进程。

一句话：**偶发仍可能；一重启网站基本就好。** 下次若再出现，把报错原文发我，我帮你重启并修。
