RobeWhisper · 第 11 期正式流程（真机最小联调）
========================================
前置：第 1–10 期已收口（PHASE9/10_ACCEPTANCE_PASS）；本机 mock 演示稳定。
本回合：只出方案，不写第 11 期业务代码（对齐「先方案后逐步击破」）。

一、本期目标
--------------------------------
在「实验室有执行节点」的前提下，完成**最小真机联调**：
同一套 TaskSpec 经 HTTP 或 ROS2 真正发出去，网站能看到成功/失败摘要，
默认仍安全关闭，不误发。

相对第 5 期（已有 HttpRobot / RosRobot 骨架 + 开关）：
从「接口预留」→「可按清单联调、可验收、可写回实验旁路信息」。

相对第 12 期：本期**不要求**真机回传完整 trajectory（那是 RSR 硬门槛）。


二、绝不堵死 12–15 的硬约束（本期设计红线）
--------------------------------
[x] 不改 TaskSpec / SimResult / ApiResult 主字段名
[x] 不拆 BaseRobot.execute_task；HTTP/ROS 仍发送同一 TaskSpec JSON
[x] 默认 USE_REAL_ROBOT=false；缺配置/无 rclpy 一律回退 Mock，不崩站
[x] 真机结果可写入实验旁路（如 robot_result / robot_ack），不吞原始 TaskSpec
[x] 不把「无真机轨迹」写成唯一终局；为第 12 期预留 trajectory 回传字段扩展点
[x] 不做接触抓取成败裁判（第 13 期）；不做 steps[] 多步（第 14 期）
[x] 不做 3D 主视口、不做公网部署、不强制激活 Kimi（第 15 期 / 后期提醒）
[x] Pipeline 主链不变：NL → LLM → TaskSpec → 闸 → engine →（可选）robot

口诀：第 11 期只把「送单窗口」在实验室真正打开一次，不加新货币、不做真回流。


三、可行性
--------------------------------
| 项 | 评级 | 说明 |
|---|---|---|
| HTTP 联调 | 高 | HttpRobot 已落地；需实验室端 POST 接收服务 |
| ROS2 联调 | 中 | RosRobot 骨架已有；依赖 rclpy + 实验室节点 |
| 无真机开发 | 高 | 用本地假接收端 / 故意错地址验友好失败 |
| 网站展示 | 高 | 已有 robot_result 摘要位；可加强「真发已开」警示 |
| 堵死 12–15 | 低风险若守红线 | 见第二节 |

自主定案：
- **优先 HTTP 桥**做「最小联通」（零基础、无 ROS 机也可验）
- ROS2 作为同契约第二条通道，有环境再勾；不强依赖
- 实验室执行节点协议约定：接收 `{"task_spec": {...}, "source": "robewhisper"}`，
  返回 JSON 含至少 `ok` / `message`（可选 `trajectory` 留给第 12 期）


四、不超过 5 个小步骤
--------------------------------
步骤1：联调契约与实验室检查单刷新
  - 固化「请求/响应最小 JSON」说明（可扩写现有 真机联调检查清单）
  - 明确：ack 字段可增不可改主契约；trajectory 可选
  - 验证：文档可勾选；无真机时仍可读懂「要准备什么」

步骤2：本地假接收端 + HttpRobot 端到端烟雾
  - 提供/加固一个最小本地 echo 服务（仅联调用，默认不随网站启动）
  - USE_REAL_ROBOT=true + ROBOT_BACKEND=http 指向假端 → 成功 ack
  - 错地址 → 友好失败，不崩
  - 验证：smoke；默认配置仍为 mock、不误发

步骤3：Pipeline / 实验旁路写回真机结果
  - 成功/失败的 robot_result 进入实验 JSON 旁路（便于答辩展示「发过真机」）
  - run_snapshot 或旁路可记 robot backend / endpoint 主机名（脱敏，不含密钥）
  - 验证：落盘含 robot 摘要；TaskSpec 主字段未改

步骤4：网站「真发」安全提示与一键自检入口
  - 能力区/诊断：真发开着时强警示；关着时明确「不会动真机」
  - 可选：页面或脚本「自检 HTTP 桥是否通」按钮（只读探测，不发危险动作）
  - 验证：mock 演示路径不变；开真发时文案不会误导

步骤5：第 11 期验收 + 回归 + 「未堵死 12–15」检查表
  - smoke_phase11；复跑 phase9/10 与关键真机烟雾
  - 书面勾选第二节红线；更新总规划第 11 期状态
  - 勘误入库
  - **明确不写**：真轨迹 RSR、接触抓取、云部署、Kimi 充值（留给 12–15 / 后期提醒）


五、步骤顺序
--------------------------------
1 契约/清单 → 2 假端 HTTP 打通 → 3 落盘旁路 → 4 网站安全提示 → 5 总验


六、本期故意不做
--------------------------------
- 第 12 期：真轨迹回流、伪对照降级为非默认
- 第 13 期：接触物体 / grasp_success
- 第 14 期：多步 steps[]
- 第 15 期：3D、公网部署、Kimi 充值激活（见 core/后期完善提醒_11到15.txt）
- 力矩优化、视觉伺服、换臂标定全流程


七、实验室依赖（需你方确认）
--------------------------------
最小联调二选一即可：
A. HTTP：一台能跑 Python 的电脑 + 接收 POST 的小服务 + 机械臂驱动由实验室已有程序消费 TaskSpec
B. ROS2：已装 rclpy 的工控机 + 订阅约定 topic 的执行节点

无实验室设备时：本期仍可用「假接收端」完成软件验收，真臂动作留到有设备日再勾清单。

--------------------------------

[x] 不提前做第12期真轨迹，避免范围膨胀
[x] 默认关真发，防演示机误连实验室
[x] 云部署/Kimi 仍钉在后期提醒，不进本期必做
[x] 红线写进第二节，步骤5强制检查
