RobeWhisper · 第 13 期正式方案 · 接触抓取试机
========================================
日期：2026-09-13
前置：第 1–12 期已收口（含能力可见打磨）。
本回合：只出方案 + 自行评估可行性，不改网站代码。
触发动手：你说「开始步骤1」后再逐步击破。


一、本期一句话目标
--------------------------------
让「抓/放」从**只动关节的示意**，升级为**可演示的接触试机**：
仿真里能看见「够没够到物体 / 有没有发生接触」，并把结果写进诊断与实验旁路。

「接触抓取试机」在这里的含义（务必对齐）：
- ✅ 教学/试机级：场景里有物体；抓取过程可读接触或接近结果；失败有人话原因
- ❌ 不是：工业夹爪力控、视觉找红积木、仿真成功=现实已抓住、上岗话术


二、你的产品能获得什么（相对第12期）
--------------------------------
| 维度 | 现在（1–12） | 第13期之后 |
|---|---|---|
| grab/place | 关节轨迹示意；target 多为标签 | 可选接触场景；有接触/接近度量 |
| 成败语义 | 「仿真跑通」≠抓住物体（文案已提醒） | 额外给出接触试机结果（成功/未接触/场景未开） |
| 场景 | 内置臂无自由物体 | 新增接触试机场景（默认可关，不破坏旧演示） |
| 答辩故事 | 能联真机 + 真/伪 RSR | 还能演示「试抓有没有碰到」 |

现实落地用处：
- 试机前先暴露「够不着 / 穿模乱碰 / 根本没接触」等软件侧问题
- 为以后真机试抓留同一套旁路字段（如 grasp_proxy / contact），不绑死某一家夹爪 SDK


三、现状盘点（推导依据）
--------------------------------
已有：
1. MuJoCo 引擎 + 摩擦/阻尼白名单；SimResult.metrics 可扩展
2. action=grab/place 已能解析并跑轨迹
3. 诊断已写明「成功≠现实抓住物体」
4. TaskSpec / 安全闸 / 真机送单 / RSR 管道已稳定

缺口（第13期要补）：
A. `models/builtin_arm2` **没有自由物体、没有夹爪**，无法谈真实接触抓取
B. 引擎不读 contact；metrics 无接触相关字段
C. 网站/诊断没有「接触试机」专用结果行
D. 若强行改默认模型，可能打断 1–12 已验收的演示路径


四、绝不堵死 14–15 / 不破坏已有交付的硬约束
--------------------------------
[ ] 不改 TaskSpec / SimResult / ApiResult **主字段名**（接触结果只进 metrics / 旁路）
[ ] 不拆 BaseRobot.execute_task；真发默认仍关
[ ] 默认演示路径可继续用无物体臂（接触场景可选或独立 model_ref）
[ ] 不做视觉伺服 / 不自研力控夹爪 / 不上岗话术
[ ] 不做多步 steps[]（第14期）；不做公网部署（第15期）
[ ] 不把「接触试机成功」写成「现实已抓住」


五、自主定案（范围怎么切才可行）
--------------------------------
采用 **「接触试机代理（grasp proxy）」**，分两档清晰交付：

档 A（本期必做 · 高可行）：
- 新场景 MJCF：桌面 + 可动物体（freejoint 方块）+ 现有臂末端（ee）作「探头」
- grab 执行后统计：是否发生接触 / 末端与物体距离是否进入阈值 / 物体是否被带动
- 输出旁路指标（示例名，实现时可微调）：
  - `metrics.contact_detected`（bool）
  - `metrics.grasp_proxy` ∈ {ok, no_contact, no_scene, uncertain}
  - `metrics.object_moved`（可选）
- 网站诊断一行人话；实验 JSON 可落盘上述字段

档 B（本期不做或仅预留）：
- 双指夹爪开合 + 力/扭矩阈值判定
- 相机识别红色积木位姿
- 真机夹爪闭环成功判定

理由：档 A 用现有 MuJoCo 能力即可验收；档 B 会把第13期拖成小论文级工程，违背「试机平台」定位。


六、自行评估可行性
--------------------------------
| 项 | 评级 | 理由 |
|---|---|---|
| 新增接触场景 MJCF（桌+物+臂） | **高** | 标准 MJCF；可与 builtin_arm2 并存 |
| 读 MuJoCo 接触对 / 距离代理 | **高** | API 成熟；可单测 |
| metrics 旁路 + 诊断文案 | **高** | 与第9/11期旁路模式一致 |
| 默认不破坏无物体演示 | **高** | 独立 model_ref 或开关 CONTACT_SCENE |
| 物体被「抓住并稳定提起」强物理 | **中** | 无夹爪时只能做弱代理（接触+位移），须文案标明 |
| 与真机夹爪成功对齐 | **中低** | 依赖实验室夹爪与感知；本期只留字段口 |
| 工业级抓取成功率优化 | **低** | 明确不做 |

总体结论：
- **第13期按档 A 做：可行，建议做。**
- 风险主要在「用户误以为已经能抓稳」——用诊断硬文案 + grasp_proxy 命名化解。
- 无真机、无夹爪 SDK 也可完整验收档 A。


七、不超过 5 个小步骤
--------------------------------
步骤1：接触场景与开关契约
  - 新增模型（建议名）：`models/builtin_arm2_contact/model.xml`（臂+桌+自由方块）
  - 约定：默认仍可用 `builtin_arm2`；接触试机切换到 contact 模型（网站下拉或说明）
  - 旁路字段名写入书面约定（只增 metrics，不改主契约）
  - 验证：新旧模型都能 load；默认烟雾不被迫换模型

步骤2：引擎接触/接近度量
  - MujocoEngine 在 run_task 结束（或步进后）汇总接触
  - 无接触场景时：`grasp_proxy=no_scene`，不报假成功
  - 有场景 + grab：根据接触/距离/物体位移给出 ok / no_contact / uncertain
  - MockEngine：给可预测的假指标，保证无 MuJoCo 时也能测文案
  - 验证：单元烟雾三种结果可复现；坏场景不崩

步骤3：Pipeline / 诊断 / 实验落盘
  - 成功回复与「最近一次诊断」增加接触试机一行
  - 实验记录可含 metrics 摘要（脱敏，无密钥）
  - 验证：无场景时人话提示「当前模型无物体，只是关节示意」；有场景时能看出接触结果

步骤4：网站能力区与演示样例
  - 能力清单一览增加「接触试机」说明（默认怎么开、不是上岗）
  - 样例按钮或剧本勾选：切换 contact 模型 → 抓 → 看诊断
  - 验证：零基础能按文案走通；关接触场景时旧演示仍顺

步骤5：总验 + 回归 + 勘误
  - 烟雾：无场景 / 有接触 / 无接触；复跑 phase12、feature_visible、phase9 相关
  - 书面确认：未改主字段名；未默认开真发；未承诺现实抓住；未堵死第14期多步
  - 勘误入库；总规划第13期勾完成态


八、步骤顺序

1 场景契约 → 2 引擎度量 → 3 诊断落盘 → 4 网站演示 → 5 总验
