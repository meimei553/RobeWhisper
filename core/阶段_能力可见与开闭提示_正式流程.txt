RobeWhisper · 能力可见与开闭提示（小打磨方案）
========================================
日期：2026-09-13
前置：第 1–11 期已收口；默认 mock / 真机关 / RSR 关。
本回合：只出方案，不改网站代码（对齐「先方案后逐步击破」）。

一、本期目标（你刚定的口径）
--------------------------------
1. **具有的功能要被看到**——真机、RSR、云端 API 等能力在网站上一眼能看见（默认关也要看见「有这个功能」）
2. **是否开启成功要有提示**——关 / 已开且正常 / 想开但失败（人话原因）

不做：第 12 期真轨迹 RSR 硬门槛业务；不做接触抓取；不做公网部署；不强制充值 Kimi。


二、绝不堵死 12–15 的硬约束
--------------------------------
[x] 不改 TaskSpec / SimResult / ApiResult 主字段名
[x] 不拆 BaseRobot.execute_task / 真机送单语义
[x] 默认仍安全关闭：USE_REAL_ROBOT=false、USE_REAL_SIM_REAL=false、LLM 演示用 mock
[x] 页面提示只增不删安全默认；不把「网页一键真发」做成无确认的危险开关（若要加开关，必须二次确认+醒目警示）
[x] 不写死伪对照为唯一终局（为第 12 期留真轨迹优先口）
[x] Pipeline 主链不变


三、可行性
--------------------------------
| 项 | 评级 | 说明 |
|---|---|---|
| 能力清单可见 | 高 | 能力区扩展即可 |
| 真机开闭提示 | 高 | 第11期已有横幅+HTTP自检，补「状态一行」即可 |
| API 开闭/自检 | 高 | 已有配齐判断；加只读探测（不写密钥到页面） |
| RSR 开闭提示 | 高 | 勾选已有；补「真轨迹/伪对照/未执行」状态条 |
| 网页直接改 .env | 中低 | 零基础方便但有安全风险；本期建议「看见+提示+自检」，开关仍以 .env 为主（可选步骤里讨论） |

自主定案：
- **本期重点 = 看见 + 状态提示 + 只读自检**，不急着做「网页写 .env」
- 真机沿用已有 HTTP 自检；API/RSR 补齐同级体验
- 专业词继续白话/小括号


四、不超过 5 个小步骤
--------------------------------
步骤1：能力清单「一眼看见」
  - 能力区固定三块卡片/列表：真机发送、RSR 虚实校准、云端语言 API
  - 每块写清：是什么、默认关、打开要改哪里（.env 键名一句人话）
  - 验证：关着时也能看见这三项存在；文案零基础能懂

步骤2：统一「开闭状态条」
  - 每项三态：关（安全）/ 已开且就绪 / 想开但未成功
  - 失败态必须带一句原因（例：未填网址、API 缺密钥、已回退 mock）
  - 验证：故意配错 .env 时页面出现失败提示，不崩站

步骤3：API 只读自检按钮
  - 「自检云端 API 是否通」（不展示完整密钥；失败人话）
  - 未配齐时按钮可点，直接提示缺什么
  - 验证：mock 演示路径不变；配齐且有额度时提示成功（余额不足时友好失败）

步骤4：RSR 状态提示加固
  - 勾选旁/诊断区明确：未执行 / 伪对照 / 真轨迹（若有）
  - 关着时写清「不会做校准」
  - 验证：默认关文案正确；勾选跑一句后能看出用了哪种对照

步骤5：验收 + 回归 + 勘误
  - 烟雾：三块可见、三态文案、API 自检、RSR 提示；复跑 phase11 相关
  - 书面确认：未堵死第12期；未默认打开真机/API
  - 勘误入库


五、步骤顺序
--------------------------------
1 看见清单 → 2 开闭状态 → 3 API 自检 → 4 RSR 提示 → 5 总验

七、和「打开时是否不方便」的关系
--------------------------------
做完本方案后：
- **看见**：不再「不知道有这个功能」
- **开成没**：页面直接告诉你成功或失败原因
- **打开动作本身**：仍主要靠改 .env + 重启（安全）；比现在少猜、少踩坑
若以后仍觉改 .env 麻烦，再单开「可选：页面引导/开关」方案。
